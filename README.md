# Web Worker 并行排序（可中断 · 分块 + 归并 · 实时 Canvas 进度）

生成 100 万个随机 `Int32`，用 4–8 个 Web Worker 并行排序，主线程全程可交互。
支持暂停 / 继续 / 取消，Canvas 实时展示每个分块与整体进度，内置完整异常降级链路。

## 运行

直接用浏览器打开 `index.html`（Worker 源码由 `Blob` 从同一份 `sort-core.js`
动态拼装，`file://` 下即可运行，无需构建、无第三方依赖）。

或用任意静态服务器：

```bash
python3 -m http.server 8080
# 打开 http://localhost:8080/index.html
```

Node 端核心 / 协议测试：

```bash
node test.js
```

## 文件

- `sort-core.js` — 同一份源码运行于主线程、Blob Worker、Node 三处：
  - 可中断的自底向上归并排序 / 二路归并（`step(budgetMs)` 时间片状态机）
  - Worker 协议：`sort` / `merge` / `pause` / `resume` / `cancel` / `ping` / `fault`
- `app.js` — 主线程编排：数据分片生成、任务图、Worker 线程池、心跳看门狗、
  降级链路、主线程分片执行、Canvas 渲染、顺序无关的多重集校验
- `index.html` — 界面（控件、Canvas、响应性测试区、日志、校验面板）
- `test.js` — Node 正确性 / 可中断 / Worker 协议测试

## 关键设计

- **不卡顿**：数据生成、树状归并（主线程降级时）、结果校验全部走
  `requestIdleCallback`（不支持时回退 `setTimeout`），每片 ≤ 8ms；Worker 内
  每片 ≤ 12ms。排序归并计算在 Worker 线程。
- **暂停 / 继续 / 取消**：Worker 在每个时间片边界检查暂停标志，暂停后不再被
  调度（0 CPU）；取消调用同步的 `worker.terminate()`，页面实测并展示终止耗时。
- **精确进度**：叶子排序按 `n·ceil(log2 n)` 次放置、归并按元素数，再用基准
  测得的 `SORT_WEIGHT` 换算为可比 CPU 工作量，整体与单任务进度均按真实成本加权。
- **异常链路**：
  - Worker 创建失败 → 只用成功的 Worker；全失败 → 重建单个 → 仍失败 → 主线程
  - Worker 崩溃 / 冻结 / 静默 → ping/pong 看门狗（心跳超时 / 进度停滞）判定死亡，
    任务重投；存活耗尽 → 重建 1 个 → 再失败 → 主线程
  - 内存不足 → 先降为单 Worker 降低并发峰值，再降主线程；主线程 OOM 给可读提示
  - 输入数据对叶子任务保留独立副本，Worker 死亡后可无损重投
- **结果校验**（不使用内置 `sort` 对比）：严格相邻有序 + 32 位总和 +
  FNV-1a 多重集指纹（异或折叠，顺序无关），三者同时与原始数据匹配才算通过。
- **故障注入**（页面下拉）：创建失败 / 运行中冻结（模拟消息丢失）/ 静默 / 崩溃。

## 验收对照

| 要求 | 实现 |
| --- | --- |
| 排序 100 万时页面可点击、滚动 | 计算全在 Worker / rIC 分片；页面内置点击 / 滚动 / CSS 动画测试区，编排测试中主线程定时器最大抖动约 19ms |
| 取消后 200ms 内所有 Worker 停止 | 同步 `terminate()`，页面显示实测终止耗时；测试中所有线程 200ms 内退出 |
| 进度误差 < 5% | 按 CPU 成本加权的工作量模型，端到端实测误差 < 2% |
| Worker 创建失败自动降级且结果正确 | 多 Worker → 单 Worker → 主线程三级降级，降级后多重集校验通过 |
